# One-time upgrade of a saved page

Use only in an authenticated desk-owner chat. Scheduled routines and other desk users stop and give the owner this procedure. Normal refresh never guesses the mode or source of a legacy page. Keep the exact saved URL; never create an artifact or overwrite Settings.

1. Read the saved Settings dashboard_link or report_artifact, verified live/training sheet and mode, and desk_owner. Read that exact existing page and its actual title. Read any available snapshot/source/status metadata. Any known contradictory mode or sheet, even partial metadata, stops for owner repair; confirmation cannot override another desk. Confirm missing files through a successful file-list/metadata read at that same URL, or successfully parse partial metadata. Permission errors, failed reads and unverified listings never count as missing and stop the upgrade. Confirmed missing or partial metadata qualifies for this one-time upgrade.
2. Build fresh data from the verified sheet with its actual completed-read receipt under the normal scripts/guards. Never infer an old read time or add a live label to unknown old content. For dashboard, build its full snapshot.json; include the configured current index.html only if that legacy asset needs updating. For reports, rebuild all five pages together with coherent status.json and source.json. Preserve unrelated files.
3. Show the owner the exact existing title and saved URL, intended training/live mode and source sheet, the fresh build's As of time and completed-read time, the proposed fresh data change, and every file to be updated. Offer Save / Change / Cancel. Change revises and needs a new preview. Cancel and Other write nothing. Save is the final approval for that exact fresh refresh and first metadata files, never metadata-only relabeling.
4. After Save, re-read the exact Settings URL/mode/sheet and page title/available metadata. Changes require a new preview and Save; contradictions stop. Run desk-report scripts/lib/legacy-bootstrap.cjs with this verified state: context owner-chat; authenticated actor identity matching desk_owner; exact decision Save; proposal with kind, url, title, mode, sheet_id, refresh true, read_at, run_id, as_of, exact files, optional dashboard asset_update; current Settings kind/url/mode/sheet_id; verified_page read_ok/url/title; metadata_read with the actual same URL, verified true and state missing or partial from successful reads/listing; actual completed provenance; build.files with the exact actual path/content payloads from the fresh scripts (all five report HTML pages with matching embedded metadata plus source/status, or full privacy-pruned snapshot and optional configured index); existing available metadata. The helper writes nothing and refuses missing authority, uncertain source, changed approval or contradictory metadata.
5. Only after authorization, update the approved files at that same saved URL. Dashboard writes its full fresh snapshot, plus index only when listed. Reports write all five fresh pages plus status/source together. Read back exact run_id/as_of/mode/sheet and the required files before success. Otherwise retain the URL and report Published but unverified only to the owner; reconcile before retrying. Never bootstrap automatically in an unattended run. Once established, all later refreshes use normal publication-target checks.
